The complement of true is true, except when it's false

72 points · 28 comments · dryperspective.github.io

A C++ deep-dive explains a counterintuitive corner case: because bitwise operators on sub-int types (including bool) trigger integral promotion to int, `~true` computes as -2 at the int level, which then converts back to bool via boolean conversion, where any non-zero becomes true — so `~true == true` under the standard. The post further shows that applying this to an enum with an explicit bool underlying type can flip the result to false specifically on GCC, due to a GCC-specific code path for converting an int back to such an enum.

What the comments said

  • Technical clarifications on why -1 (all bits set) isn't used as "true" in C++ given its multiple possible bit-widths, unlike BASIC or Forth conventions.
  • A tangent connecting the behavior to fields of characteristic 2 in abstract algebra, though others noted this doesn't map directly since the article concerns complement, not negation.
  • Several pointed out GCC already warns about `~` on a bool expression under -Wall, so careful compilation would catch the footgun.
  • General commentary comparing C++'s accumulated arcane rules to Perl's reputation for "write-only" surprises.
