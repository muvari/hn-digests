1 Open Source

OpenLogi

1,547 points · 409 comments · openlogi.org

OpenLogi is a local-first, open-source (MIT/Apache-2.0) alternative to Logitech's Options+ software, written in Rust, letting users remap buttons, set DPI, and control SmartShift scroll behavior directly over the HID++ protocol. It requires no account and sends no telemetry, works over Bolt, Unifying, and Lightspeed receivers, Bluetooth, or USB, and stores bindings in a plain, portable TOML config file. It ships signed installers for macOS, Linux, and Windows, though features like per-app profiles and full device pairing are still in progress.

What the comments said

  • Many commenters welcome a local, open alternative to Options+, echoing a common complaint that Logitech's software has long lagged behind its hardware.
  • A recurring gripe is that the project's website (and possibly the app copy itself) reads as obviously LLM-generated, which several found distracting even while liking the underlying tool.
  • People pointed to existing alternatives — the paid, decades-old Steermouse and the Linux-focused Solaar — sparking debate over how much open-source licensing actually matters versus just "working well."
  • Some accused the project of being a reskin of LinearMouse; others pushed back, linking the GitHub repo as evidence the code is original.
  • A side thread noted Logitech does offer a lesser-known offline/air-gapped installer for Options+, with jokes about pairing that with a Bluetooth keyboard.

6 OSINT

Geolocating a random island using geometry and CUDA programming

469 points · 78 comments · yassa9.github.io

This writeup documents solving an OSINT geolocation challenge — identifying a resort's island from a single photo using geometry and brute-force GPU search rather than tools like Google Lens. After finding no useful EXIF/GPS metadata, the author builds a triangular "fingerprint" from the relative positions of three visible landmasses, then filters over 141,000 global land polygons from OpenStreetMap data through tropical-latitude, density, and clustering heuristics down to roughly 23,500 candidate island clusters. From those it generates over 80 million candidate triangles and matches them against the photo's geometric fingerprint using a custom CUDA kernel that assigns one matching thread per candidate triangle.

What the comments said

  • Reactions are overwhelmingly impressed, praising the creativity and rigor of solving the puzzle geometrically instead of just using image-search tools.
  • Several commenters draw parallels to competitive human "geoguessing" (e.g., GeoGuessr players like Rainbolt) who memorize visual patterns to locate photos without any computational pipeline.
  • Commenters highlight how valuable OpenStreetMap's open data is for this kind of OSINT work, noting it performs even better in populated areas thanks to richer tagging like roads and shops.
  • One reply notes newer LLM-plus-OSM tools could enable similar lookups via natural-language queries, though this was a tangent rather than the main focus.
  • Several commenters specifically praise the author's disclaimer that no LLM was used to write the post, reflecting broader HN fatigue with AI-generated content.

16 Systems Programming

Solo – a .so loader for static Linux binaries

200 points · 233 comments · github.com

SoLo lets a fully static, musl-linked Linux executable dynamically load glibc-linked shared objects at runtime — notably the host's proprietary Vulkan and OpenGL GPU drivers — without bundling a second libc, a container, or an AppImage. It works via a custom ELF loader (x86-64 and aarch64) plus a glibc ABI compatibility shim built on musl, and ships a demo that runs a real Vulkan compute shader through unmodified host drivers on AMD, Intel, NVIDIA, and Apple M1 (Asahi) hardware. The project's CI reportedly validates the approach against shared libraries from the 1,000 most-installed Debian packages.

What the comments said

  • Technical commenters debated whether reimplementing dynamic-linking/ELF-loading semantics is wise, with some arguing glibc's dynamic linking model is fundamentally broken compared to how Solaris, Darwin, and Windows handle similar problems.
  • Others explained the underlying problem plainly: musl doesn't perfectly emulate glibc's ABI, so a statically-linked musl binary can't reliably dlopen glibc-built shared objects without a bridge like this.
  • Several commenters flagged that the README and much of the codebase appear heavily LLM-generated (pointing to commit history as evidence), sparking pushback about not writing documentation by hand.
  • The project author actively engaged in the thread, defending the "fully static" claim with verification commands and pressing critics to focus on technical substance over authorship complaints.
  • Commenters broadly agreed GPU driver distribution is the crux of Linux packaging pain SoLo addresses, drawing comparisons to the workaround pain of Flatpak/AppImage (e.g., losing HIP support).

22 Mathematics

Palomar: A registry of Lean verified mathematics

178 points · 39 comments · terrytao.wordpress.com

Terence Tao announces Palomar, a new registry for machine-checked mathematics proofs written in the Lean proof assistant, incubated by the Lean FRO and ICARM, and positions it as a "preprint server" analog for formal proofs. Submissions are GitHub repo snapshots containing a formal "challenge" statement, a "solution module" proof, and a formalization.yaml plain-language description; Palomar mechanically verifies the proof typechecks (via a tool called Comparator) and uses an LLM to check the informal description matches the formal claim. Tao stresses this falls short of full peer review — it's a clearinghouse, not a journal — and notes he already test-submitted his own formalization of Sendov's conjecture.

What the comments said

  • Commenters ask what incentivizes people to submit; others compare it to the intrinsic motivations behind arXiv preprints or open-source contributions.
  • A recurring clarification thread: Lean guarantees the *formalized* statement is true, but there's still an unavoidable human leap in verifying that the formal statement faithfully captures the informal claim.
