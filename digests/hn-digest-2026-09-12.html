660 points · 523 comments · autom.dev

7 Programming

Stabilizing Rust's Never Type

233 points · 90 comments · lwn.net

After more than two years of work, Rust has stabilized the "never" type (!), used to denote computations that never return — letting the compiler optimize away impossible error branches (e.g., an infallible string conversion) and giving infinite loops or diverging code a coherent type for inference. Stabilizing it required a subtle, technically-breaking change to the compiler's inference fallback: prior to Rust 2024, ambiguous cases defaulted to the unit type (), but the 2024 edition changed the fallback to ! itself, matching how never-typed values actually behave.

What the comments said

  • Several debated the choice of ! as syntax, preferring an explicit Never alias; others defended it as consistent with !'s pre-1.0 use for divergent return types.
  • A thread explained why ! coerces to any type but can't implement Default — Default requires actually constructing a value, which ! by definition never can.
  • One commenter argued the feature undercuts Rust's usual strictness about implicit conversions; others countered that no real runtime conversion ever happens since no ! value is ever produced.
  • Readers shared a related conference talk by the change's author and noted parallel interest from TypeScript users familiar with its own never type.
