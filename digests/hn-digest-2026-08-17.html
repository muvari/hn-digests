1 AI & ML

Qwen 3.8 27B is excellent, but it defaults to overthinking things

767 points · 365 comments · simonwillison.net

Simon Willison tests Qwen 3.8 27B, a new Apache-2 licensed vision-capable 27B model from Alibaba's Qwen lab, running locally via LM Studio on a MacBook Pro and an NVIDIA DGX Spark. He finds the model capable of excellent output (the best pelican-riding-a-bicycle SVG he's gotten from a local model, plus strong bounding-box detection) but says its default "xhigh" reasoning effort causes absurd overthinking, such as 21 minutes and 22,000+ reasoning tokens spent on a simple SVG, or an elaborate animated circle produced when a plain circle was requested. His practical recommendation is to run the model at low or no reasoning effort instead of the shipped default.

What the comments said

  • Commenters compare Qwen against the terser "Muse Glimmer" 30B model, though some argue the comparison is unfair since Glimmer performs worse despite being faster.
  • One user reports an 11-hour run on dual GPUs versus roughly 20 minutes for GPT-5.5 on the same task, prompting debate over whether extra "thinking" time is worth the quality gain.
  • Multiple workarounds are proposed: a LoRA ("ThinkingCap") that cuts thinking tokens by about 40% with similar quality, proxies that force-stop generation after a token budget and redirect the model, and llama.cpp's --thinking-budget flag.
  • General consensus that shipping xhigh as the default reasoning effort was a poor choice, with low reasoning recommended as more reliable than medium, which can get stuck looping.
  • A tangent emerges about Apple Silicon's memory bandwidth limitations constraining local LLM inference speed, with hope expressed for HBM in future hardware.

AI;DR (AI; Didn't Read)

836 points · 517 comments · rickmanelius.com

Rick Manelius proposes "AI;DR" (AI; Didn't Read) as a new social convention for dismissing unedited, unreviewed AI-generated writing shared in newsletters, Slack messages, and social posts. He argues that if a person isn't willing to review and edit AI output before sharing it, readers shouldn't be expected to read it either, while carving out exceptions like customer-support copy where fully AI-generated text is already the norm.   • A recurring debate centers on whether judging AI text by its prompt is fair: some say a short prompt reveals low effort, while others counter that for legitimate agentic tasks (like generating an incident report from logs) publishing the prompt is meaningless or would erase the tool's value entirely.

3 AI Ethics

Anthropic's ‘watermark’ text adulteration in Claude is a perversion of writing

785 points · 693 comments · daringfireball.net

John Gruber criticizes Anthropic's new EU-mandated watermarking of Claude's text output, which Anthropic initially described as "imperceptible" and not affecting meaning, quality, or readability. He explains that the actual mechanism is a form of semantic steganography: at each token-generation step, words are deterministically sorted into "green" and "red" lists via a secret key, and the model is nudged toward green-list choices so the output can later be statistically identified as AI-generated. Gruber argues this necessarily degrades word choice despite Anthropic's claims to the contrary, and objects to the company's initial refusal to explain how the system actually works.

What the comments said

  • Commenters question how watermarking can work for code or tightly constrained outputs where word-choice flexibility is minimal, with some speculating it explains recent increases in verbose, unnecessary code comments.
  • Strong objection to terms-of-service language barring users from removing watermarks, which some read as undermining ownership of generated text, alongside skepticism that the policy will meaningfully apply outside the EU.
  • A technical dispute breaks out over whether watermarking truly "adulterates" output: some argue token sampling is already probabilistic so this just makes the randomness deterministic, while others counter that it adds genuine new constraints and can make already-likely tokens even more dominant rather than flattening the distribution.
  • Several comments explore copyright implications, since AI output is itself uncopyrightable, debating whether watermarking helps resolve authorship disputes or mainly risks falsely flagging human writers who used Claude only for proofreading.
  • One commenter notes that forcing an LLM to pick less-natural tokens is reminiscent of running models at very low temperature, which is already known to produce stilted, unnatural-sounding prose.

A Preview of DuckDB v2.0

618 points · 111 comments · duckdb.org

The DuckDB core team previews v2.0 ("Cyanoptera"), shipping this fall with a new SQL parser, a new default storage format, a reworked C API, and a large batch of new features built from over 10,000 commits. Headline additions include a native client/server mode via the "quack" extension and new CONNECT statement (letting one DuckDB attach to and query another, or push SQL directly to remote Postgres/MySQL databases), a first-class VARIANT type for fast, schema-flexible semi-structured data with shredded Parquet support, and full trigger support (BEFORE/AFTER, row- and statement-level, with transition tables). Collectively the release marks DuckDB's expansion from a purely in-process engine toward a networked, multi-tenant, server-capable database.

What the comments said

  • Several commenters see this release as DuckDB shifting from an embedded execution engine toward becoming the foundation of a cloud data warehouse, drawing comparisons to MotherDuck.
  • Broad enthusiasm for the project's portability, with people describing adopting it across multiple companies specifically for its ability to do out-of-core, bigger-than-memory processing on modest hardware.
  • Interest in the new async I/O for serving live HTTP traffic, plus questions about WASM/browser runtime footprint, with estimates of the binary landing around 10-20MB.
  • Practical questions about how DuckDB compares to SQLite for embedded use cases and to distributed engines like AWS Athena/Trino, including whether DuckDB is meant for distributing work across machines or staying local.

Reticulum – Decentralized Mesh Network

224 points · 76 comments · reticulum.network

Reticulum is an open-source, cryptography-based networking stack that lets anyone build sovereign, censorship-resistant local and wide-area networks using cheap, readily available hardware (LoRa radios, Wi-Fi, TCP, and more), and it can keep working over very high-latency, low-bandwidth links. Rather than routing by fixed addresses, it uses self-sovereign, portable cryptographic identities, and it never transmits unencrypted packets, offering forward secrecy by default. The project frames itself less as a single network than as a toolkit for spinning up many independent, interoperable mesh networks free of central control or kill switches.

What the comments said

  • Several commenters note the name echoes the fictional "Reticulum" internet from Neal Stephenson's novel Anathem, with some speculating (unconfirmed) that it inspired the project's naming.
  • A recurring technical debate concerns anonymity claims: while Reticulum strips source addresses from packets, commenters point out that hop counts and periodic "announce" packets can still let observers with multiple interfaces roughly triangulate a node's location, especially over LoRa.
  • Commenters compare Reticulum to other mesh/overlay projects (Tailscale, ZeroTier, Netbird, Yggdrasil, cjdns), generally agreeing that VPN-mesh tools solve a different problem (connecting your own devices) versus Reticulum's goal of large-scale independent multi-hop routing.
  • Some criticize the lack of a formal published specification, since the reference Python implementation is treated as the de facto spec, though others push back, saying a spec does exist and that at least one clean-room reimplementation has been built from it.
  • A lighter subthread jokes about the word "reticulum" having anatomical/biological connotations, noting it's also the name of the endoplasmic reticulum and a ruminant's stomach chamber.
