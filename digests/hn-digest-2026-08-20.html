1 Privacy & Security

AliExpress runs silent WebAudio fingerprinting that breaks Bluetooth multipoint

954 points · 299 comments · blog.laserphile.com

A user investigating why AliExpress silently disrupted his Bluetooth multipoint headphones traced it to two hidden WebAudio contexts created by Alibaba's obfuscated anti-fraud scripts (collina.js and fireyejs.js). The scripts generate a silent oscillator tone, run it through an AnalyserNode to fingerprint subtle differences in the browser's audio processing, and route it (at zero gain) to the system audio output, which is enough to keep the OS audio/Bluetooth pipeline actively engaged even though nothing is audible. The same bundles also collect canvas, WebGL, hardware, timing, and interaction data for a broader device fingerprint, likely feeding fraud/bot-detection scoring.

What the comments said

  • Multiple commenters confirm they've independently noticed the same symptom, on both the AliExpress website and its iOS app, sometimes for months, describing the phone/car audio 'freaking out' as if picking up a mic command.
  • Several suggest audio playback should require explicit permission like camera/microphone access, though others note this could be a nuisance since users may want AliExpress's product videos to play.
  • Some point out that tab/OS mute controls don't stop this because there's no conventional media element for them to target, which is exactly what makes the technique sneaky.
  • One thread speculates this fits a known pattern among some Chinese apps of using background audio/tricks to keep the app 'alive' and inflate active-user metrics, prompting questions about why Apple's App Store review didn't catch it.
  • A commenter asks for a plain-language explanation of how silent audio can fingerprint a device, which another answers by describing how hardware/driver differences alter the processed waveform in measurable ways.

711 points · 291 comments · experimental-history.com

What the comments said

  • Several see relevance to AI: with software and writing increasingly automatable, some argue 'thickness' and humanities-style depth may become one of the more durable, differentiating human skills.
  • Multiple commenters reflect on the pedagogical challenge described: English teachers often had their own personal epiphany about a book's depth but struggle to convey that depth to students who aren't yet mature enough to get it, creating a recurring generational cycle.
  • A science-themed aside links the idea to the xkcd 'purity' comic, suggesting the same thickness/depth-reward dynamic applies within scientific fields, not just the arts.

5 Security

Malicious Rust crate Arrayref runs a build-time payload

480 points · 409 comments · safedep.io

SafeDep reports that a compromised maintainer account published a malicious version 0.3.10 of the popular Rust crate arrayref, which added a dependency on a typosquatted crate impersonating dtolnay called proc-macro1 (not the legitimate proc-macro2). The proc-macro1 build script decodes a base64-obfuscated C2 address and, purely by compiling a project with the tainted dependency, downloads and silently runs an architecture-specific binary (via a dropped executable on Unix or a hidden PowerShell/VBScript combo on Windows), all before any application code runs. The attacker also yanked older clean arrayref versions to funnel Cargo users toward the malicious 0.3.10, and crates.io has since removed the malicious packages.

What the comments said

  • Commenters note this mirrors long-standing npm-ecosystem supply-chain attack patterns now migrating to Rust/Cargo, and point out Cargo lacks pnpm-style controls to flag or block new install/build scripts.
  • A debate emerges over whether restricting build.rs scripts would meaningfully help, with some arguing attackers would simply shift to compromising test code instead, making it only a minor inconvenience.
  • Several discuss why these attacks target developer build machines rather than end-user runtime, concluding dev machines hold valuable cloud credentials and are comparatively unprotected (no antivirus, expected to run untrusted code), unlike shipped applications which face more scrutiny before reaching users.
  • Multiple people ask why package registries still allow unaudited publishing after so many prior supply-chain incidents, with responses noting that auditing at ecosystem scale is an unfunded, unsolved coordination problem, though efforts like cargo vet and cargo crev exist.
  • Commenters cross-link to the official Rust blog advisory and other vendor writeups (JFrog, StepSecurity, Aikido) confirming and adding detail to the incident.

What the comments said

  • Some compare the concept to existing MIDI/chord tools like Scaler 3 and envision live-jamming setups where the model reacts to a player's chords in real time, effectively becoming a 'third musician.'

10 Engineering

Git at any scale

331 points · 104 comments · cursor.com

A Cursor engineering blog post (authored by a former key GitHub infrastructure engineer) argues that Git's distributed, packfile-based design is fundamentally mismatched to centralized, at-scale hosting: because Git repositories are content-addressable DAGs where each object lookup depends on the previous one, naive distributed key-value storage of objects (as tried by Google via JGit and a DHT) works logically but performs poorly since packfiles still must be assembled and sent over the network for every clone/fetch. It frames three possible scaling strategies — distribute the filesystem, distribute the packfiles, or distribute Git itself — as background for describing Cursor's own system, which uses S3's atomic compare-and-swap for a stateless, consensus-light write-ahead log so any server can act as primary.

What the comments said

  • Strong praise for both the technical writing and the author's pedigree (prior GitHub infrastructure work plus Vitess/PlanetScale experience), with several commenters saying it substantially raises their opinion of Cursor's engineering organization.
  • Many highlight the design's reliance on S3's strong consistency and 11-nines durability guarantees rather than building custom distributed storage, drawing parallels to classic database internals (write-ahead logs, compaction) and predicting the approach will influence other Git-hosting projects like Forgejo, Gitea, and Tangled.
  • One technical correction/question challenges the post's claim that its 3-phase-commit-based replication only requires majority acknowledgment, since 3PC classically requires full agreement from all nodes.
  • A recurring, separate thread pushes back not on the technology but on trust in Cursor's ownership/leadership (invoking Elon Musk and recent Grok privacy issues), with multiple commenters saying they would refuse to host code there regardless of the engineering quality — while others note this reaction seems based on a misunderstanding of Cursor's actual ownership.
11 Programming

Turns are Better than Radians (2022)

340 points · 202 comments · computerenhance.com

Casey Muratori argues that programmers should stop converting angles to radians (or even tau) before calling trig functions, because fast sin/cos library implementations immediately convert radian input back into a normalized [0,1] or similar range internally anyway. Using "turns" (0 to 1 for a full circle) as the native angle unit eliminates a wasted multiply-then-divide round trip, produces exact floating-point representations for common angles like 90/180/270 degrees, and requires only a small wrapper or renamed function to adopt, with legacy radian-based code still supported via a thunk.

What the comments said

  • Several commenters raised the classic calculus objection: d/dx sin(2*pi*x) = 2*pi*cos(2*pi*x), so turns reintroduce a tau factor once you need derivatives, meaning the trick mainly helps direct evaluation, not calculus-heavy code.
  • A side debate emerged about whether angles have units at all, with some arguing radians/degrees/turns are all dimensionless ratios and math purists (citing Spivak) treating unit-tagging as a category error, while others (from a physics/engineering view) insisted units matter in practice.
  • Commenters extended the idea to other domains, noting waves and signal processing already effectively use "turns" as cycles, and gradians and other historical divisor-friendly units were mentioned as alternatives with their own tradeoffs.
  • Some pushed back on universally renaming standard trig functions, worried about confusing other fields where sin/cos legitimately take radians (e.g., phase angles), suggesting new turn-based function names instead.
  • A technical side-thread discussed whether compilers could auto-elide the pi-multiply/divide round trip, concluding it would require fast-math flags and library-level visibility (e.g., C23's sinpi/cospi) since floating point makes the transforms non-equivalent in general.

18 AI & ML

DiffusionGemma Technical Report

152 points · 37 comments · arxiv.org

Google's DiffusionGemma technical report introduces an experimental open-weight language model that generates text via discrete diffusion, refining blocks of 256 tokens in parallel instead of decoding one token at a time. It was produced by fine-tuning the Gemma 4 mixture-of-experts model (3.8B activated/25.2B total parameters) using under 10% of the original model's training budget, via a two-stage pipeline of supervised bidirectional denoising followed by RL plus sampler distillation. The result achieves roughly 1,500 output tokens/second on a single H100, far outpacing even speculative-decoding AR models, while retaining thinking mode, multimodality, long context, and even fallback AR generation ability.

What the comments said

  • Commenters are enthusiastic that diffusion models make much better use of single-GPU compute than autoregressive decoding, with several sharing their own reimplementations (a macOS/Metal port hitting ~15 tok/s, a Rust+CUDA port) and community explainer writeups.
  • There's technical debate about denoising as a strategy, with one commenter citing Kaiming He's research suggesting predicting noise is representationally inefficient compared to directly predicting the data surface.
  • Some discuss the clever trick of using output-distribution entropy to adaptively adjust the number of diffusion steps, and note this doesn't transfer to image diffusion since it lacks explicit probabilities.
  • Speculation about whether diffusion models can close the remaining accuracy gap with AR models is mixed — no theoretical reason it can't be closed, but skepticism given years of attempts against highly optimized AR architectures.
  • One commenter argues drastically faster generation (1500 tok/s) would force a rethink of compilers and test tooling to keep pace with LLM-driven coding, sparking pushback about language-specific bottlenecks like Java stack traces or slow Rust compilation.

20 AI & ML

Stop Anthropomorphizing Intermediate Tokens as Reasoning/Thinking Traces (2025)

228 points · 153 comments · arxiv.org

This ICML 2026 position paper by Kambhampati et al. argues that referring to LLM intermediate tokens (chain-of-thought output produced before a final answer) as 'reasoning' or 'thinking traces' is a harmful anthropomorphization, not a harmless figure of speech. The authors contend this framing falsely implies the traces resemble human reasoning steps or provide a genuine interpretable window into the model's process, and that this confusion misleads both practitioners' use of these models and the research agenda built around them.

What the comments said

  • Many commenters relate personally to the paper's core critique, describing watching models say things like 'wait, that's wrong' in their reasoning trace and then immediately repeat the identified mistake anyway.
  • A recurring alternate framing casts intermediate tokens as 'scratch space' or a self-generated context that helps attention retrieve relevant information, rather than genuine derivational reasoning.
  • Commenters are split on practical value: some say they actively monitor thinking traces to catch models heading in the wrong direction early and save time/tokens, others argue the traces should be treated as black boxes since only the final answer matters.
  • A tangent draws a comparison to human 'aha' moments, with someone noting that in humans such flashes without a clear preceding chain are cited as evidence of consciousness, while here the same discontinuity is used to deny LLMs are 'really' thinking.
