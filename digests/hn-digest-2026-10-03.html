3 Operating Systems

FTL: A new operating system for clouds

185 points · 73 comments · ftl-os.org

FTL is a new "library OS" design for cloud containers: rather than a monolithic kernel, each container runs a full userspace OS — process model, VFS, TCP/IP — as a linked library talking to a minimal FTL kernel through a small, hypervisor-like interface. It's binary-compatible with existing Linux applications (FTL's own website runs on an unmodified Linux HTTP server binary) while aiming for VM-grade isolation at container-like performance. The roadmap through early 2027 adds a filesystem, Node.js/Go support, and SMP/Arm support.

What the comments said

  • Commenters debated the right taxonomy for FTL — exokernel, unikernel, or something closer to gVisor or Microsoft's Drawbridge — without reaching consensus on which prior art it most resembles.
  • Several noted the project's own ASCII architecture diagram rendered broken in some browsers, which undercut the pitch for a few readers.
  • One detailed comment argued FTL is best understood as a classic exokernel: keeping only the minimum needed to multiplex hardware in-kernel, pushing everything else (TCP stack, VFS) to userspace with capability-based security.
  • A security-minded commenter tied renewed interest in alternative isolation models to a recent KVM/VM-escape zero-day.
  • General optimism that the project dogfoods itself — serving its own site from a real Linux binary — was seen as a credible proof point for an early-stage OS project.

8 Security & Privacy

Cloudflare OHTTP gateway

195 points · 93 comments · blog.cloudflare.com

Cloudflare launched a closed beta of its OHTTP (Oblivious HTTP) Gateway, complementing its existing OHTTP Relay (formerly "Privacy Gateway"). OHTTP splits a request across two independently operated hops — a relay that hides client identity and a gateway that decrypts the request content — so no single party sees both who made a request and what it contains. The new gateway lets customers whose app servers already sit behind Cloudflare use a third-party relay, closing a gap where Cloudflare previously couldn't act as both relay and gateway for the same customer without breaking OHTTP's trust-separation model; it's used today by things like Apple's Private Cloud Compute and iCloud Private Relay.

What the comments said

  • Some joked about Cloudflare's growing centrality to internet infrastructure ("ClInternet"), tying it to the company's broader default-blocking of unregistered bots.
  • A notable concern was that privacy tooling like this is easiest to exploit for sophisticated bad actors (e.g., state-sponsored hackers) while being too complex for the average person who'd benefit most — though others clarified this protects inbound traffic to servers, not attacker anonymity.
  • Several were skeptical that true anti-tracking is achievable given how much of the web requires JavaScript and cookies, with counterarguments that it's entirely possible for developers who deliberately choose not to tie data to identity.
  • A commenter noted iCloud Private Relay already uses OHTTP today on all recent Apple devices, as one of the technology's largest existing deployments.

24 Security

How to hack time, with C2PA

45 points · 6 comments · da.vidbuchanan.co.uk

Security researcher David Buchanan demonstrates a flaw in C2PA (the content-provenance standard behind camera "authenticity" metadata): the spec allows signers to declare arbitrary byte-range "exclusions" from what's covered by a cryptographic signature, and nothing stops a malicious signer from excluding the entire file. He proves this by producing an image with a valid, trusted timestamp signature that was then "photoshopped" after the fact without invalidating any signature — effectively forging a backdated, tamper-proof-looking photo — and argues the fix is to tightly restrict which byte ranges each file format is allowed to exclude, rather than leaving it unconstrained as the spec does today.

What the comments said

  • One commenter wryly compared the flaw to similar signature-exclusion mistakes previously made in SAML, suggesting this is a recurring class of spec-design bug.
  • Another connected the finding to long-standing dread about remote attestation and trusted-computing schemes only ever becoming more pervasive and harder to audit.
  • A commenter raised the stakes given the EU AI Act's requirement that AI content generators embed C2PA manifests, arguing C2PA's provenance model is poorly suited to proving content wasn't AI-touched in the first place, since it can only attest to the most recent signing step.
