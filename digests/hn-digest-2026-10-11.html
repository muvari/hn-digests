2 AI & Math

Terence Tao: Math 2.0 [pdf]

479 points · 471 comments · teorth.github.io

This is a slide deck from a Caltech talk by mathematician Terence Tao exploring what he calls "Math 2.0" — mathematics done jointly by humans and AI systems, including formal tools like Lean. Among its arguments is a thought experiment about alignment and understanding: would you want a human expert to understand the mechanism behind an AI-derived cure before it's used, drawing an analogy to trusting opaque but effective AI-generated mathematics.

What the comments said

  • The cancer-cure analogy dominates the thread — many argue it's weak since medicine already approves treatments whose mechanisms aren't fully understood, and that most people would take a working cure regardless of whether anyone understands why it works.
  • Others defend the deeper point: AI-driven science may need to be studied empirically, like biology, rather than understood symbolically, and mathematics may be approaching the same kind of reckoning.
  • Some worry an AI collaborator could still waste effort on technically-correct-but-useless results (e.g., absurdly impractical complexity bounds), or that reliance on Lean could sideline the intuition of "blackboard mathematicians."
  • A few worry heavy AI use will flatten the diversity of mathematical schools of thought that historically drove real progress.

  • A side-thread proposes simpler signature-based auth schemes, with replies noting that's essentially what passkeys already are, and that the hard part is trustworthy key storage, not the protocol.

15 Programming

The tilde in your PATH may not be your HOME

246 points · 162 comments · disconnect3d.pl

Writing export PATH="$PATH:~/.local/bin/" in a quoted assignment doesn't expand the tilde to your home directory, because tilde expansion only applies to unquoted tilde-prefixes — the fix is to use $HOME explicitly instead. The author demonstrates how this silently creates a literal ./~/.local/bin/ directory that shells will still execute binaries from.

What the comments said

  • Several confirm this is standard POSIX behavior, not bash-specific, and note bash has extra variants like ~+/~- for $PWD/$OLDPWD.
  • Some prefer prepending $HOME/.local/bin before the rest of PATH rather than appending it, so a malicious local script can't shadow system binaries like sudo.
  • A broader tangent argues most shell path/quoting headaches would vanish if filenames were restricted to a small safe character set, though others counter that would unfairly break non-English filenames.
  • One recalls an AI coding agent once creating a literal directory named "~" in a repo — the same tilde-as-text versus tilde-as-home collision.

Valen's Memory Safety: A New Kind of Borrow Checking

168 points · 96 comments · verdagon.dev

Valen, a new language from Vale creator Evan Ovadia, implements "group borrowing" — a relaxed borrow-checking approach that catches use-after-free bugs at compile time while allowing patterns normally rejected by borrow checkers, like multiple local variables mutating the same object. It relaxes Rust's "shared-xor-mutable" rule to "no use-after-free," and the idea has already influenced other languages including Google's Carbon.

What the comments said

  • Technical readers debate naming, weighing "Group Borrowing" against the author's proposed rename "Path Borrowing," since "groups" misleadingly implies an explicit group type.
  • Several ask whether this relaxed borrow-checking could be "backported" into Rust itself; the author notes Rust's Polonius project already thinks in terms of "paths," and a WIP "Exclusion Typing" project is attempting something similar.
  • The author clarifies Valen is a new project, not a Vale rename, reusing ~90% of the Vale compiler but differing enough (Rust interop, mutable aliasing) to warrant its own name.
  • A side-discussion on whether language research should prioritize GPU/SIMD-friendly designs gets a reply confirming GPU compilation (via Rust MIR, SPIR-V, or MLIR) is on Valen's roadmap.

Diffle is a keyboard-first, vim-inspired diff viewer that runs in the browser: it reviews git diffs, PR branches, or commit ranges, starts per-language LSP servers for jump-to-definition and hover, and lets you collect line/block/file comments into a prompt for an AI agent or export them as a pending GitHub PR review.

What the comments said

  • A reviewer notes they already do most code review now inside an AI harness rather than reading raw diffs, and asks how others keep up with review volume as AI-generated code output scales.
  • Interest in Diffle's comment-to-prompt workflow leads one commenter to request a live mode where an agent can listen and respond to comments in real time; the maintainers say they've discussed it but are weighing polling versus an agent-side endpoint.
  • Some compare Diffle to their own homegrown fzf/vim-based diff review setups and say the keyboard-first bindings would feel familiar.
  • One asks whether a heavily AI-assisted tool "feels" vibe-coded in its UX; the maintainer says real design effort went into avoiding that despite the AI-assisted implementation.

Getting old Macromedia Director Games to run on modern Hardware

96 points · 16 comments · werwolv.net

The author works through three layered copy-protection schemes on a childhood German point-and-click adventure game (decoy duplicate files on the disk image, a CD-check reading a leftover config file from a previous game, and a check embedded in the Macromedia Director projector executable itself), using tools like ProjectorRays and Ghidra to extract and patch the game's embedded Director script.

What the comments said

  • Commenters note LLMs can now do much of this work directly — one links a frontier-LLM-built web port of a related game in the same series, done in about two hours, arguing there's "basically no reason left" for manual reverse engineering if you only care about the end result.
  • Others push back that LLM-based translation still needs a way to run and compare against the original binary to verify correctness, so this kind of manual groundwork remains valuable.
  • The ScummVM project is cited as already working on native ports of many Director-based games, with a community-tracked status page.
  • Longtime Director/Lingo developers reminisce about building interactive CD-ROM and early web/ad-agency projects with it before moving on to Flash/ActionScript.
