1 Privacy

Fingerprints are the new cookies

733 points · 357 comments · royfish.dev

Written from the perspective of an ad-tech fingerprinting script, the post argues that browser/device fingerprinting has quietly replaced third-party cookies as the web's primary tracking mechanism, walking through Google's multi-year "deprecate cookies" saga that ended in fingerprinting being explicitly permitted in its ad products. It explains the technical mechanics: network data (IP, headers) is fragile, but hardware signals (GPU, CPU, memory, display, audio stack, fonts) are stable enough that combined they make most devices practically unique, and surveys which browsers (Brave, Tor, Mullvad) actually defend against it.

What the comments said

  • Many commenters share a resigned "cool tech, horrifying privacy invasion" reaction, with some describing switching to JA3/JA4 fingerprinting at the CDN layer themselves for anti-abuse rather than tracking.
  • A sub-thread debates whether EU consent banners ever targeted cookies themselves versus the tracking behind them, with some arguing enforcement against fingerprinting is already technically illegal but poorly applied.
  • Several people push back on "nothing to hide" apathy, arguing persistent identification across sites/devices is harmful even when "anonymized."
  • Practical defense tips dominate the rest: Brave's fingerprint randomization ("farbling"), Tor/Mullvad's uniformity approach, and anecdotes of the EFF's Cover Your Tracks tool correlating sessions across VPNs and incognito mode.

3 Programming

A Modern Web App in C

654 points · 281 comments · prophitt.me

The author shipped a commercial product, marketyour.games, built entirely in C using the "BCHS" stack — OpenBSD, C, its built-in httpd, and SQLite — serving everything through CGI, including HTML generated directly in C and all static assets compiled into the binary. The post argues CGI's reputation as obsolete doesn't hold up in 2026: deploys are copying one statically-linked binary, there's no framework or templating layer to learn, the dependency footprint is just libcurl, libsodium and a vendored single-file JSON/SQLite library, and OpenBSD's pledge/unveil/chroot give solid sandboxing for free.

What the comments said

  • Several commenters pile on the demo site's unreadable monochrome design, with the author admitting it's a rough first pass and confirming the blog post itself was human-written, not AI-generated.
  • A substantial thread argues CGI's per-request process-forking is exactly what FastCGI/long-lived-process models were invented to avoid, citing ~8ms fork overhead, though others note the simplicity tradeoff is the whole point.
  • People point out most of the architectural benefits (minimal deps, simple debugging, no reverse-proxy split) apply equally to Go or Rust, which also get memory safety — prompting some "why C specifically" pushback that the author doesn't fully answer.
  • Practical CGI-revival tips circulate: nginx-cgi plugin, lighttpd's native CGI support, and Passenger/Rack as a Ruby equivalent of the same pattern.
4 Hardware

Turn a WiFi 7 Router into a 320Msps Software Defined Radio Receiver

393 points · 106 comments · github.com

This project reverse-engineers a Gemtek W1700K Wi-Fi 7 router's MediaTek MT7996 radio chipset, replacing its stock firmware with custom code that turns it into a wideband SDR receiver capable of capturing 320 Msps of 14-bit IQ data across 2.4/5/6 GHz bands, streamed over the router's 10GbE port to a host that renders a live spectrum/waterfall view in the browser. The repo includes a ground-up MT7996 bring-up sequence decoded register-by-register from MediaTek's own firmware traces, with no vendor code reused.

What the comments said

  • Strong enthusiasm from the ham-radio/SDR crowd, calling it a breakthrough that could enable full 13cm/5cm amateur radio bands at a fraction of typical SDR hardware cost.
  • Several commenters suspect (and the author doesn't deny) heavy use of an AI coding agent for the reverse-engineering grind, given the dense, oddly-phrased low-level register documentation in the README — with mixed reactions ranging from skepticism to treating it as a legitimate existence proof for AI-assisted RE work.
  • Hardware-focused replies note the same chipset likely works on the Banana Pi R4, and discuss practical uses like repurposing it as a cheap high-performance service monitor.

587 points · 283 comments · github.com

A GitHub issue reports that since version 0.157.0, OpenAI's Codex CLI silently starts a persistent background daemon on first use that copies the entire ~374MB platform package to disk, auto-updates itself hourly (killing active turns mid-update), and inherits whatever environment variables (like proxy settings) were present when it first launched — persisting even after the CLI window closes, requiring several manual steps to fully kill. Secret of Orange Cats Revealed After 60-Year Search

271 points · 184 comments · sciencealert.com

Two independent research teams identified the genetic cause of orange cat fur: a small deletion near the Arhgap36 gene on the X chromosome that massively increases its expression in developing pigment cells, shifting melanin production toward reddish/yellow pheomelanin instead of black/brown eumelanin. Because the gene is X-linked, this also explains the long-standing mystery of why most orange cats are male while females tend to get calico or tortoiseshell patchwork patterns from X-inactivation.

What the comments said

  • Many commenters enjoy debunking (or embracing) the "orange cats are dumb" stereotype, drawing parallels to similarly unfounded stereotypes about redheaded humans and dog breed behavior.

  • Some international commenters note "orange cat" vs. "ginger cat" terminology differences between the US and UK.
  • A few push back on the claim that Arhgap36 overexpression is harmless outside melanocytes, noting the gene causes developmental issues when dysregulated in other species.

Type-safe HTML templating in Zig

245 points · 97 comments · lalinsky.com

The author built "zt," a Zig HTML templating library modeled on Go's Templ, that transpiles JSX-like template files into Zig code at build time so templates can import application types and vice versa, catching type errors (like a typo'd struct field) as ordinary compiler errors.   • Some push back gently on using an LLM to write the accompanying blog post, though others defend it as clearly human-written based on how it reads.
  • General agreement that template engines exist specifically to prevent HTML/XSS injection bugs that arise from manual string concatenation.
