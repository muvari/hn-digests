4 Networking

Tailcat – Like netcat, but over Tailscale’s data plane

640 points · 119 comments · github.com

Tailcat is a new open-source tool from Tailscale that works like netcat but tunnels traffic over Tailscale's WireGuard-based data plane (magicsock/DERP) without requiring a Tailscale account or control plane. Both a CLI and Go library, it lets one side run a listener that generates a short connection token, which the other side uses to connect — traffic is end-to-end encrypted, starts via a DERP relay, and upgrades to a direct peer-to-peer connection when NAT traversal succeeds. It supports piping stdin/stdout, exposing local TCP ports, an auth-free SSH server, a SOCKS5 proxy, and acting as an exit node, and can use Tailscale's free public DERP relays or self-hosted ones.

What the comments said

  • Several commenters praised it as a clean, no-lock-in way to get NAT traversal without needing a Tailscale account, and author Brad Fitzpatrick responded directly to reassure that it keeps working even if Tailscale-the-company disappears, as long as you run your own DERP server.
  • Some pushback framed Tailscale's core value proposition as just "avoiding port forwarding," which a few argued is negative-value compared to just opening a port directly if you have a public IP.
  • Others noted it's similar in spirit to existing tools like magic-wormhole, and compared it to the recently launched bitbang-cli as a competitor.
  • A tangent thread praised Brad Fitzpatrick's decades-long track record (memcached, LiveJournal, Go's http2) and noted he's still actively maintaining Go's HTTP/2 code a decade after his well-known talk on it.

16 Security

When str.lower() is a security vulnerability in Python

176 points · 74 comments · sethmlarson.dev

Python Software Foundation security developer-in-residence Seth Larson explains a vulnerability (CVE-2026-17084) in Python's IDNA 2003 domain-name encoding: the case-folding step incorrectly used the live, version-varying str.lower() instead of the frozen Unicode 3.2.0 rules the underlying spec requires, causing different Python versions to encode the same Unicode domain name into different ASCII (punycode) representations. The fix hard-codes exceptions so str.lower() behaves as Unicode 3.2.0 would within this function; the danger is that this kind of implementation/spec mismatch can create parser differentials, letting two components of a system disagree about what domain a string actually represents.

What the comments said

  • The top request was for a clearer explanation of the actual exploit path, which the author supplied: it's a parser-differential bug, similar in spirit to SSRF-enabling URL-parser mismatches, where one system component "sees" a domain name differently than another.
  • A related, more opinionated sub-thread argued Python's broader handling of "decoding" DNS names into Unicode is fundamentally wrong for security-sensitive contexts like TLS certificate Subject Alternative Names.
  • Some discussed other Unicode case-folding surprises in Python, like "ß".upper() returning "SS", which can silently change string length and break assumptions.
  • A commenter linked a related historical Spotify security incident involving creative Unicode usernames as another real-world example of this class of bug.

Mold: A Massively Parallel Linker

175 points · 29 comments · arxiv.org

This ASPLOS 2027 paper by Rui Ueyama, creator of the mold linker, formally describes mold's design: applying data parallelism systematically across the entire linking pipeline by decoupling architectural bottlenecks like symbol resolution and archive processing that prevented earlier linkers from scaling across cores. Benchmarked on large real-world C++ programs, mold links multi-gigabyte debug binaries in seconds — 2.4–16.1× faster than LLVM's lld and up to 112× faster than GNU ld — with an ablation study showing the speedup comes cumulatively from parallelizing every pass rather than any single trick.

What the comments said

  • The newer Rust-based "Wild" linker was highlighted as currently benchmarking somewhat faster than mold, though commenters noted Ueyama has already found further ~1.5× speedups for mold that aren't fully released yet.
  • Several praised mold's real-world impact, including one report that switching to it as the default linker shaved hours off a full build in the Stagex Linux distribution.
  • A recurring theme: commenters connected the paper's observation that drastic linker improvements tend to come from new linkers, not incremental changes, to a broader pattern where new entrants can take architectural risks established tools cannot.
  • The author's minimal, request-driven approach to open-source stewardship — quickly shipping niche feature requests — drew appreciation from a user relying on mold for an unusual binary-patching workflow.

What the comments said
