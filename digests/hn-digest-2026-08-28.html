Just the rumour of a bug is enough to find an exploit these days

345 points · 115 comments · anil.recoil.org

OCaml maintainer Anil Madhavapeddy recounts fixing a cohttp path-traversal bug and seeing automated exploit probes hit his live server within minutes of opening the public fix PR — before any patch or advisory was released — and notes he could trivially reproduce the exploit himself using an LLM agent given only a vague description of the bug. He argues this breaks the traditional embargo model of security disclosure, citing research showing mean time-to-exploit has gone negative (exploitation now precedes patching) and real cases like marimo's and Langflow's CVEs being exploited within hours, and calls for restructuring open-source security response around 'bugonomics' — improving defender/maintainer remediation throughput rather than relying on secrecy.

What the comments said

  • Other maintainers corroborate the trend firsthand, e.g. rclone's maintainer describing a jump from ~20 security disclosures in 10 years to 40+ in a single month, now requiring AI-assisted triage.
  • Some push back that this isn't conceptually new — inferring exploits from rumors/commits is an old practice — but agree LLMs have massively scaled and democratized it to low-skill actors.
  • Discussion of memory-safe languages as only a partial fix, since LLMs still find logic-level and C-binding vulnerabilities even inside memory-safe codebases like OCaml.
  • Frustration that organizational incentives haven't caught up: commenters describe managers pressuring for feature speed over shipping already-fixed, already-verified bug fixes.
  • Practical mitigation ideas raised, like batching security patches into grouped PRs and being wary of how bug-bounty programs multiply report volume.

Migrating to HTTPX2

201 points · 91 comments · github.com

OpenAI's Python SDK migration guide explains that its HTTP layer now uses HTTPX2 instead of httpx; default-client usage is unaffected, but a notable behavior change is that HTTPX2 no longer bundles certifi and instead verifies TLS certificates against the operating system's trust store, which can break certificate verification in minimal containers or environments with corporate TLS-inspecting proxies unless SSL_CERT_FILE/SSL_CERT_DIR or an explicit SSLContext is configured. What the comments said

  • Simon Willison explains the context: HTTPX2 is a compatibility-preserving fork by a different maintainer, created because the original httpx project is heading toward a breaking 1.0 release under a maintainer who has restricted community discussion

Hilariously fast volume computation with the divergence theorem (2018)

258 points · 66 comments · alyssarosenzweig.ca

The author derives a fast method for computing the volume of a closed, triangulated 3D mesh by applying the divergence theorem: choosing a vector field whose divergence is 1 converts the volume integral into a surface integral that reduces to a simple per-triangle sum computable directly from vertex coordinates. The result is a cheap, closed-form GPU-friendly formula requiring no voxelization or rendering, just iterating over triangles.

What the comments said

  • Commenters enjoyed the post as clean, AI-free math writing, though several note it's a 2018 piece being recirculated

  • A side discussion compares this exact triangle-sum method to the 'naive' alternative of rasterizing/voxelizing the mesh and counting cells, noting the voxel approach trades exactness for GPU parallelism and scales with grid resolution cubed rather than triangle count
  • Readers speculate whether the author (Alyssa Rosenzweig) worked on the Asahi Linux GPU driver project; another commenter points to a Geometric Algebra derivation of the same result as an especially elegant alternative
